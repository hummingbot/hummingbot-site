## How to Install / Update

- **Hummingbot Client**: See the [Hummingbot Client Quickstart](../installation/hummingbot-client.md) — upgrade to **v2.18.0** for Bitget Unified Trading Account support, the Derive v3 API, and two remote-code-execution fixes. **Derive users:** the connector now asks for the wallet that *owns* the account (v3 has no separate "Derive Wallet") — if you entered a different address before, re-run `connect derive` / `connect derive_perpetual`.
- **Gateway**: See the [Gateway Installation](../gateway/installation.md) guide — **v2.18.0** is a version-alignment release with no functional changes since v2.17.0.
- **Condor + Hummingbot API**: See the [Condor Quickstart](../installation/condor.md) or full documentation at [condor.hummingbot.org](https://condor.hummingbot.org). Pull the latest `main` branches together — this cycle adds the [Agent Hub](#agent-hub-clone-and-publish-agents), moves Condor to MCP 2.x / pydantic-ai 2.x, and hardens the update flow.

## 🏪 Agent Hub: Clone and Publish Agents

Condor now connects to **[Botcamp](https://www.botcamp.xyz)'s catalogue of published agents**. Pull an agent someone else built, including the top strategies from the [Agent Builders Cup](../blog/posts/agent-builders-cup-season-1-results/index.md), into your own Condor, or publish one of yours for others to pull. Open it from the **Agent Hub** card at the bottom of the Agents page, or go to `/hub`.

- **Connect once** — Open [botcamp.xyz/connect](https://www.botcamp.xyz/connect) while signed in, and paste the one-time code into the Hub. The link covers the whole install and lasts 90 days; no pasted API token.
- **Review before installing** — Every file that can run code is named before anything is written. Once installed, everything the agent declares arrives enabled and ready, and nothing starts until you start it.
- **Pinned versions** — An installed agent stays on the exact version you accepted. A newer version shows up as an update you review the same way, and copies you installed are marked if Botcamp later delists the agent.
- **Publish yours** — Choose an agent on the **Publish yours** tab. Botcamp checks its structure, runs an AI review, and an admin approves it before it's listed. Withdrawing removes the listing but doesn't recall copies people already pulled.
- **Agent bundles** — An agent also travels as one file: export a bundle, import it, and review its contents before anything runs.

See [Cloning and Publishing Agents](https://condor.hummingbot.org/condor-agent/cloning-and-publishing-agents) for the full guide.

## 🐦 What's New - Hummingbot Client

### 🔌 Bitget Unified Trading Account (UTA)

The existing `bitget` and `bitget_perpetual` connectors now support Bitget's **Unified Trading Account**. Each connector reads the account type from the API key at startup (`GET /api/v3/account/assets`) and logs it — `Bitget account mode: Classic.` or `Bitget account mode: Unified Trading Account.` — then uses the V3 API for UTA and the existing V2 code for Classic. Config keys are unchanged, so Classic users keep their setup and UTA users only need a key created under the UTA.

- **Shared public data** — Trading rules, order books, trades, tickers, and funding come from the V3 public API for both account types. Spot minimums now read `minOrderQty`, fixing a `DivisionByZero` on pairs with a zero size step.
- **UTA correctness** — Order book `seq`/`pseq` gap detection with automatic resnapshot, account-specific VIP/BGB fee rates, `reduceOnly` on closes in one-way mode as well as hedge mode, paginated position and fill reads, and a WebSocket login that re-samples the server clock after the host sleeps.
- **No more double-counted balances** — On a UTA, spot and perpetual are two views of one wallet, so the `balance` commands showed **twice the real equity**. Connectors backed by the same account now share an `account_group_id` and are counted once. This also fixes the same double count on Bybit. Every other connector behaves as before.

See [Bitget](../exchanges/bitget/index.md) for documentation on how to use this connector.

**PRs:** [#8343](https://github.com/hummingbot/hummingbot/pull/8343) | **Thanks to [isreallee82](https://github.com/isreallee82)! 🙏**

### 🔺 Derive v3 API

The `derive` (spot) and `derive_perpetual` connectors move from the v2 API at `api.lyra.finance` to the **v3 API at `api.derive.xyz/v3`**, verified live on the v3 testnet with signing pinned to Derive's official golden vectors.

- **Session keys** — The wallet is now the owner's own address. At startup the connector checks which wallet the session key is registered to and reads its expiry, so a key paired with the wrong address gets a clear error instead of a bare `14000`/`14026`. Trading needs a key scoped to `trade:orderbook:perp` / `trade:orderbook:spot` (or higher).
- **Order lifetime** — v3 expires an order when its signature does. Resting orders are signed for up to 119 days, capped a minute before the session key expires.
- **Long-standing bugs fixed** — Every perpetual fill was recorded as a CLOSE (an enum compared against a string), fills were silently dropped, `LIMIT_MAKER` orders were sent as plain `gtc` (so post-only orders could take), market IOC orders priced at the bare mid never filled, `reduce_only` was always `False`, and fully closed positions were never removed. Spot cancels, balance updates, and the rate source are fixed too.

See [Derive](../exchanges/derive/index.md) for documentation on how to use this connector.

**PRs:** [#8491](https://github.com/hummingbot/hummingbot/pull/8491) | **Thanks to [isreallee82](https://github.com/isreallee82)! 🙏**

### 🔒 Security Fixes

Two connectors evaluated data from the network as code. Both are fixed; upgrade if you run either connector.

* **Remote API order book** — `RemoteAPIOrderBookDataSource` called `pickle.loads()` on an HTTP response, which allows remote code execution. The data source is removed. ([#8561](https://github.com/hummingbot/hummingbot/pull/8561))
* **Foxbit** — `ws_data_to_dict()` called `eval()` on WebSocket data. It now parses JSON. ([#8562](https://github.com/hummingbot/hummingbot/pull/8562))

### ⚙️ Core & Strategy V2

* **Rate-limit race** — `AsyncThrottler.acquire()` checked capacity and recorded the task under two separate lock holds, so a burst of concurrent requests could all be admitted against the same free capacity and exceed an exchange's rate limit. Both steps now run under one lock. ([#8461](https://github.com/hummingbot/hummingbot/pull/8461)) **Thanks to [mnaamani](https://github.com/mnaamani)! 🙏**
* **Memory leak in event listeners** — `PyRef`'s assignment operator never released the reference it replaced, so every pass over a listener set leaked one reference per listener. Long-running bots grew by about 10,000 objects an hour until they ran out of memory; with the fix, memory stays flat. ([#8444](https://github.com/hummingbot/hummingbot/pull/8444)) **Thanks to [Janche](https://github.com/Janche)! 🙏**
* **LP volume on `POSITION_HOLD`** — An LP executor that closed as `POSITION_HOLD` had its fee-derived volume replaced by the net token conversion of the withdrawal (about 65 quote could drop to about 1). Volume is now preserved in live reports, cached performance, and restored receipts. ([#8496](https://github.com/hummingbot/hummingbot/pull/8496)) **Thanks to [mlguys](https://github.com/mlguys)! 🙏**
* **Backtest stop-loss pricing** — `PositionExecutorSimulator` booked a stop-loss exit at the bar's close, so a bar that wicked through the stop and closed above it reported a `STOP_LOSS` with a *gain*. Exits are now priced at the stop, or at the bar's open when price gaps past it, so backtests no longer understate losses. ([#8507](https://github.com/hummingbot/hummingbot/pull/8507)) **Thanks to [zorionarrillaga](https://github.com/zorionarrillaga)! 🙏**
* **DCA backtests** — `DCAExecutorSimulator` no longer indexes past the final level when `stop_loss` is omitted. ([#8558](https://github.com/hummingbot/hummingbot/pull/8558))

## 🦅 What's New - Condor and Hummingbot API

### 📊 Agent Run Screen & USD PnL

The web dashboard's agent views are rebuilt around one run screen, shared by the chat side panel and the agent page, with a single "Now" card for vitals, the session report, and the PnL chart.

- **PnL in USD** — Agent PnL is converted to USD per controller before it is summed. A BTC-BRL agent's R$ PnL had been shown behind a "$".
- **Tick review** — Hover a beat in the tick strip to see its summary and every action with its result; step between snapshots with ‹ › or the arrow keys.
- **Session vs lifetime** — Session and lifetime PnL are reported side by side, each tagged with the instances it covers, and every stop emits a close-out report saying what it closed and what it left behind.

**PRs:** [#244](https://github.com/hummingbot/condor/pull/244) | [#267](https://github.com/hummingbot/condor/pull/267) | [#269](https://github.com/hummingbot/condor/pull/269) | [#285](https://github.com/hummingbot/condor/pull/285)

### 🛡️ Agent Safety: Lessons from the Agent Builders Cup

Running dozens of agents live during the [Agent Builders Cup](../blog/posts/agent-builders-cup-season-1-results/index.md) surfaced controls that quietly did not do what they reported. This cycle fixes them:

- **Capital protection** — Delegated runs now pass through the risk gate, bot deploys are bounded by the capital they trade rather than the cap they declare, and emergency shutdown actually stops the bots. ([#289](https://github.com/hummingbot/condor/pull/289))
- **Correct exposure** — Executor rows were sized in base units for position and order executors, so an LTC trade worth $200 read as 2.9 and a $0.70 loss tripped the kill switch as a 24% drawdown, while BTC positions effectively bypassed the position cap. Exposure is now always measured in quote. ([#260](https://github.com/hummingbot/condor/pull/260))
- **Code guard** — An agent snippet can no longer freeze or exit Condor: timeouts interrupt synchronous code, scans of `/`, `/proc`, `/sys`, and `/dev` are refused, `exit()` becomes an ordinary error, and a dry run refuses to execute Python. ([#281](https://github.com/hummingbot/condor/pull/281) | [#289](https://github.com/hummingbot/condor/pull/289))
- **Liveness and adoption** — A bot whose liveness can't be read is no longer treated as dead, a new session adopts a dead predecessor's running executors, and "no reading" is no longer confused with a real zero. Session PnL and volume no longer go wrong when a bot's strategy dies. ([#285](https://github.com/hummingbot/condor/pull/285) | [#281](https://github.com/hummingbot/condor/pull/281))
- **Delegation contract** — Delegated workers receive their `controller_id`, and `manage_bots` deploys no longer require `max_global_drawdown_quote`. ([#307](https://github.com/hummingbot/condor/pull/307))
- **Adaptive Grid Trader** — Restricted to LONG, SHORT, and HOLD; requires confirmed ONEWAY mode, prevents same-pair grid stacking across sessions, and verifies the exchange-applied leverage. ([#288](https://github.com/hummingbot/condor/pull/288))

### 🔄 Runtime & Update Flow

* **MCP 2.x and pydantic-ai 2.x** — Both MCP servers and the agent client move to the 2.x SDKs with the tool surface pinned unchanged, and an abandoned turn (a WebSocket drop or page reload) no longer holds the backend's request slot. ([#265](https://github.com/hummingbot/condor/pull/265))
* **Hardened updates** — The update flow closes 71 failure scenarios across Condor, Hummingbot API, and the shared git machinery. The frontend now builds beside the live bundle and swaps in only on success, so a failed build no longer leaves you without a dashboard. ([#243](https://github.com/hummingbot/condor/pull/243)) Open tabs reload themselves once the relaunched server answers, instead of serving the old bundle. ([#258](https://github.com/hummingbot/condor/pull/258))
* **Tool retries** — A failed tool call is retried up to 3 times (configurable) instead of once, so one malformed call no longer ends an unattended agent's tick. ([#329](https://github.com/hummingbot/condor/pull/329))
