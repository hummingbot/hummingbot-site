## Release Highlights

### 🔒 Gateway Wallet Security

Gateway **v2.15.1** is a security patch that removes three wallet API endpoints exposing dangerous server-side key operations. Hummingbot API was updated on `main` at the same time to drop the corresponding proxy routes.

**Gateway removed:**

* **`POST /wallet/create`** — generated private keys on the Gateway server
* **`POST /wallet/send`** — moved funds via the API
* **`POST /wallet/show-private-key`** — returned decrypted private keys

**Hummingbot API removed:**

* **`POST /gateway/wallets/create`**
* **`POST /gateway/wallets/send`**
* **`POST /gateway/wallets/show-private-key`**

Wallets must now be imported with **`POST /wallet/add`** (Gateway) or **`POST /accounts/gateway/add-wallet`** (Hummingbot API) using an externally generated key. Safe wallet routes (`GET /wallet`, `/add`, `/add-hardware`, `/remove`, `/set-default` on Gateway; `/accounts/gateway/*` on Hummingbot API) are unchanged.

**Breaking change:** Clients that called the removed endpoints will now receive **404** responses. Upgrade Gateway to **v2.15.1** and pull the latest Hummingbot API `main` branch together.

**PRs:** [gateway #653](https://github.com/hummingbot/gateway/pull/653) | [hummingbot-api #183](https://github.com/hummingbot/hummingbot-api/pull/183)

### 🔒 Tailscale Security

Condor and Hummingbot API now support [Tailscale](https://tailscale.com) for private, encrypted access between your devices. Connect over a tailnet instead of exposing port 8000 to the public internet—keeping order placement, balances, and bot control behind a VPN only your machines can reach.

See the [Tailscale guide](/hummingbot-api/tailscale/) for setup instructions, or read [Securing Condor and Hummingbot API with Tailscale](/blog/posts/securing-condor-and-hummingbot-api-with-tailscale/) for a full security walkthrough.

**PR:** [condor #92](https://github.com/hummingbot/condor/pull/92) | [hummingbot-api #156](https://github.com/hummingbot/hummingbot-api/pull/156)

### 🔗 Chainstack RPC Provider

Gateway adds [Chainstack](https://chainstack.com/) as a cross-chain RPC provider for both Solana and EVM networks—the first provider to use API-driven node discovery instead of URL templating. Route DEX traffic through deployed Chainstack nodes for lower latency, higher availability, and more reliable swap execution.

### 🌊 Gateway CLMM Fixes & Enhancements

Important fixes and enhancements to Gateway's concentrated liquidity (CLMM) [connectors](/gateway/connectors/) for Uniswap, Orca, and Meteora:

* **Inverted BUY price fix:** CLMM `quote-swap` on Orca and Meteora returned an inverted price on the BUY side (base/quote instead of quote/base), so the same pool reported, for example, `0.987` on BUY versus `1.012` on SELL. Prices are now consistently quoted in quote/base on both sides.
* **Real Uniswap pool balances:** Uniswap CLMM `pool-info` was reporting Uniswap V3's virtual liquidity divided by token decimals as the token amounts, which is meaningless. It now returns the pool's real ERC20 balances via `balanceOf`, matching the on-chain TVL.
* **`binCount` on `pool-info`:** The `pool-info` route now accepts an optional `binCount` parameter (Orca, Uniswap, Raydium) that returns a `bins` array describing the liquidity distribution—tick-spacing-wide bins centered on the active tick, each with its price and base/quote token amounts. This mirrors Meteora's existing bin shape across the other CLMM connectors. Default behavior is unchanged: `binCount` defaults to 0, so existing callers pay no extra RPC cost.
* **Extended Ethereum tx receipt polling:** EVM transaction execution now polls for the receipt for an additional 90s after the initial timeout, so a healthy tx that needs a few more blocks to confirm is no longer reported as a failure.

**PRs:** [#642](https://github.com/hummingbot/gateway/pull/642), [#635](https://github.com/hummingbot/gateway/pull/635)

### 🤖 OpenRouter LLM Support

Condor now supports [OpenRouter](https://openrouter.ai/) as an LLM provider for `/agent`, giving you access to a large catalog of models through a single API key. OpenRouter also offers **free models** in the picker—select one with $0 pricing to use `/agent` without being charged.

**How to use:**

1. Create an API key at [openrouter.ai/keys](https://openrouter.ai/keys)
2. Add `OPENROUTER_API_KEY=sk-or-...` to your Condor `.env` file and restart the bot
3. In Telegram, run `/agent` → **Change LLM** → **OpenRouter — Pick Model** and select from the live catalog (free models show $0 pricing)

You can also choose **Enter model manually** and send an OpenRouter slug (for example `anthropic/claude-sonnet-4-5`, or `openrouter/free` for OpenRouter's free model router) if you already know which model you want.

**PR:** [#82](https://github.com/hummingbot/condor/pull/82)

### 📡 MQTT Bridge Migration

Migrated the remote MQTT bridge from `commlib-py` to `aiomqtt`, replacing paho's uncatchable disconnect errors with catchable reconnect logic on the event loop. Bots now recover automatically when the Hummingbot API broker restarts, without the degraded-performance issues seen on reconnect.

**PR:** [#8293](https://github.com/hummingbot/hummingbot/pull/8293)
